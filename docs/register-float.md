# Register-sized floating-point helpers

Ordinary binary32 arithmetic no longer goes through the compiler-generated bytewise U128 expression tree. FADD32_REG, FSUB32_REG, FMUL32_REG and FDIV32_REG take complete raw float values in B and C and return the raw result in A. Comparison helpers use the same inputs and return a 32-bit zero or one. Signed and unsigned 32-bit integer conversions use B and return A. The compiler preserves its BC frame pointer around these calls.

Float32 arithmetic uses the 32-bit ALU, a small 32-by-32 multiplication routine when needed, and a bounded 64-by-32 division routine. IEEE packing, unpacking and sticky shifting operate directly on 32-bit register limbs. Shared binary64 packing and unpacking use the same approach. Rounding is to nearest, ties to even; signed zeros, gradual underflow/subnormals, infinities and NaN comparisons are covered. Invalid arithmetic results use a canonical quiet NaN; NaN payload preservation is not promised.

The wider stack-ABI helpers retain their existing byte layouts. This allows double arithmetic and conversions to share compact packing routines without changing C function argument slots, pointers, return conventions, object formats or the ISA. Four-byte values are assembled from four adjacent byte locations by LOAD32 and STORE32; no memory location or opcode has been widened again. No floating-point host shortcut was added to the emulator.

The compiler chooses actual integer conversion widths instead of first widening every operand/result to int128. Other software integer work uses full 32-bit limbs where its width permits, including carry, shifts and signed comparisons. Runtime dependency closure emits each required helper once per translation unit. The checked-in assembly examples and C library snapshots were regenerated with this backend.

FloatSizeCheck enforces size ceilings for these examples so a future change cannot silently restore the old expansion. FloatRegisterCheck and FloatWideCheck compare executed helper results against IEEE reference arithmetic: 25,890 binary32 arithmetic/comparison/conversion cases and 5,064 binary64 or wider-conversion cases. NaNs are compared by classification rather than payload. Integer, stack, pointer and library regression checks also pass.
